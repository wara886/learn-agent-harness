# Learn Agent Harness：DSH 三课大纲 v1

> 状态：M0 冻结稿，不含课程正文或应用实现。冻结日期：2026-08-15。
> 事实基线：`deepseek-harness@b150a551b8d465e31e418e1b2eaf5e79bbb7d28e`。
> 事实注册表：[`claims-v1.yaml`](./claims-v1.yaml)。6 条 claim 已按固定提交核验并冻结；审核记录见 [`M0-CONTENT-REVIEW.md`](./M0-CONTENT-REVIEW.md)。

## 冻结规则

- 三课依次回答“为什么先查再答”“记录怎样变成模型看到的消息”“能力为什么能加入又撤下”。
- 每课只有一个用户问题、一个核心状态变化和一个机制；状态序列只是同一变化的 2 至 3 个可观察阶段。
- 默认层先展示任务、预测、操作、变化和普通语言解释，再给机制命名。实现层与 DSH 对照层默认折叠。
- 每课只改一个变量；完成取决于实验或迁移检查的结果，不取决于点击、滚动或停留时间。
- 演示一律标记“本地确定性概念演示，不调用模型，不产生 API 费用”。演示输出不是 DSH API，也不证明模型必然作出相同判断。
- A 级表示新课或新状态机，需要事实审核和学习体验审核；claim 仍为 `candidate` 时不得进入内容冻结。

## 01 让 Agent 先查再答

| 字段 | 冻结内容 |
|---|---|
| `sectionId` | `lesson-01-tool-first-answer` |
| 用户问题 | Agent 为什么没有直接回答？ |
| 可见结果 | 用户看到 Agent 先读取示例工作区中的发布端口，再给出“端口值 + 来源行 + 已停止”；当读取结果改为拒绝访问时，结束结果改为“无法从现有结果确认”，不填造端口。 |
| 学习目标 | 用户能用普通语言解释：问题需要工作区事实，Agent 必须先取得工具结果，再把该结果用于下一次决定；用户还能预测工具结果变化会怎样改变最终回答。 |
| 前置依赖 | 会读一行键值配置；用过聊天式或编码 Agent。无需了解 DSH、事件或插件。 |
| 唯一核心状态变化 | 从“只有问题、没有工作区依据”变为“已有工具结果，并据此回答或明确无法确认”。 |
| 唯一机制 | Agent loop 中的工具调用往返。 |
| 单变量实验 | 保持任务、工具名和回答规则不变，只把工具结果从 `APP_PORT=4173` 改成 `拒绝访问`；运行前先选择“仍回答 4173”“说明无法确认”或“无限重试”。 |
| 完成检查 | 展示一个未见过的相邻场景：工具返回“文件不存在”。用户只有选择“说明缺少依据并停止”，并指出改变的是工具结果而不是用户问题，才通过。 |
| 最多 3 个新术语 | `Agent loop`：反复判断下一步是回答还是行动；`tool call`：请求外部能力执行一个动作。共 2 个。 |
| `claimId` | `dsh-agent-loop-tool-round-trip`；`dsh-tools-execute-waterfall` |
| 教学简化 | 用固定脚本代替真实模型，用单个只读工具和单次调用代替多工具调度；`APP_PORT=4173` 只是教学夹具。默认层不展示请求 header、流式 chunk、重试、取消、并行调度、作用域或工具执行 waterfall。演示中的“拒绝编造”来自固定结束规则，不是对任意模型行为的产品保证。 |
| 默认层篇幅预算 | 体验层 + 理解层共 650 至 850 个中文字符；1 个预测、1 个主操作、3 个状态行、1 个结果对比；目标 6 至 8 分钟；首次结果无需阅读术语。 |
| 展开层篇幅预算 | 最小实现 + DSH 对照共 500 至 700 个中文字符；核心差异不超过 25 行；最多 2 张 claim 卡；只解释工具往返和 `tools/execute` 的限定，不展开批量并发。 |
| 风险等级 | `A`：首次体验与新状态机。事实审核重点是“有工具调用才继续一次请求”及 waterfall 与并发调度的区分；体验审核重点是先看到因果变化，再看到术语。 |

### 状态序列

1. **只有请求：** 页面显示“找出发布端口并说明依据”，答案区为空，工作区事实尚未取得。
2. **取得结果：** Agent 选择读取工具；过程区显示工具目标和 `APP_PORT=4173`，答案区仍未结算。
3. **形成结论并停止：** 工具结果进入下一次决定；正常分支显示端口与依据，拒绝访问分支显示无法确认，两条分支都进入明确停止状态。

### 普通语言到术语

先解释“它不能只靠问题里的文字知道工作区端口，所以先去读；读到的内容回来后，它才决定怎样结束”。用户能复述这一因果关系后，再把“反复决定回答还是行动”命名为 `Agent loop`，把“请求读取能力”命名为 `tool call`。

## 02 从记录还原它看到的内容

| 字段 | 冻结内容 |
|---|---|
| `sectionId` | `lesson-02-log-to-model-view` |
| 用户问题 | 聊天界面中的消息从哪里来？ |
| 可见结果 | 用户把第 01 课的完整记录投影成较小的模型消息列表；加入一条只用于记录的待办事件后，完整记录多一行，而模型消息列表保持不变。 |
| 学习目标 | 用户能区分“为回放保留的完整事件记录”和“下一次模型请求实际使用的消息”；用户能依据事件是否进入消息表面，预测它会不会改变模型视图。 |
| 前置依赖 | 已完成第 01 课，或使用其内置回放夹具；理解“工具结果会参与下一次决定”。无需读 TypeScript。 |
| 唯一核心状态变化 | 从“只看最终文本”变为“从完整记录得到一个经过筛选和排序的模型消息视图”。 |
| 唯一机制 | Session 事件到模型消息表面的投影。 |
| 单变量实验 | 保持已有事件及顺序不变，只在末尾加入一条 `todo/write` 记录；运行前预测完整记录和模型消息列表分别是否变化。 |
| 完成检查 | 给出一条新的 `turn/end` 事件。用户只有判断“完整记录增加、模型消息不变”，并说明它记录边界而不产生模型消息，才通过。 |
| 最多 3 个新术语 | `SessionEvent`：一次被追加保存的过程记录；`surface`：当前用于生成模型消息的有序事件集合；`projection`：从记录得到模型消息的规则。共 3 个。 |
| `claimId` | `dsh-session-append-only-source`；`dsh-session-surface-projection` |
| 教学简化 | 用第 01 课的短事件夹具代替持久化 Session，不模拟 seed、replace、compaction、事件版本或缓存。概念演示把投影显示成两列，但真实 DSH 的消息来自有序 surface；`assistant/message` 的空内容例外和替换语义只在 DSH 对照的 caveat 中提示，不进入默认实验。 |
| 默认层篇幅预算 | 体验层 + 理解层共 750 至 950 个中文字符；1 个预测、1 个投影操作、2 列对照、3 个状态行；目标 7 至 9 分钟；默认只展开一条事件的解释。 |
| 展开层篇幅预算 | 最小实现 + DSH 对照共 650 至 850 个中文字符；事件样本最多 12 行，核心投影伪代码不超过 20 行；最多 2 张 claim 卡；replace 只写限制提示，不在本课教学。 |
| 风险等级 | `A`：新课与投影状态机。事实审核重点是 surface 事件集合和 log-only 排除规则；体验审核重点是避免把“完整日志”与“模型记忆”说成同一对象。 |

### 状态序列

1. **只有完整记录：** 时间线保留请求边界、用户消息、模型输出、工具结果和结束边界，用户尚未看到模型消息列表。
2. **生成模型视图：** 投影规则选出能产生消息的 surface 节点并保持顺序；边界、chunk 和只记录事件留在日志中，但不出现在模型消息列表。
3. **验证无变化：** 加入 `todo/write` 后，日志行数增加，模型消息列表与加入前逐项相同。

### 普通语言到术语

先解释“系统为了回放会记下很多过程，但下一次请求不需要把每条过程记录都当成一条聊天消息；它按固定规则取出需要的部分”。用户完成两列对比后，再依次命名 `SessionEvent`、`surface` 和 `projection`。

## 03 加一项能力，再完整撤下

| 字段 | 冻结内容 |
|---|---|
| `sectionId` | `lesson-03-register-and-remove-tool` |
| 用户问题 | 为什么新增能力不需要修改主循环？ |
| 可见结果 | 初始工具目录没有“统计文本”；挂载课程插件后目录出现该工具并能返回字符数；执行清理函数后目录恢复原样，同一任务不再看到该工具。 |
| 学习目标 | 用户能解释：主循环读取当前注册表，不需要为每个工具新增分支；注册动作必须带着对应的撤销动作，释放后能力应从同一可见集合消失。 |
| 前置依赖 | 已完成第 01 课；知道 Agent 会从可用工具中选择行动。第 02 课不是硬前置。 |
| 唯一核心状态变化 | 从“能力不可见”变为“注册后可见”，再由同一注册的清理动作恢复为“不可见”。 |
| 唯一机制 | 工具注册的 effect 生命周期。 |
| 单变量实验 | 固定任务文本和输入样本，只切换“统计文本”这一项注册是否存在；比较工具目录与运行分支，不同时改变工具实现或 Agent 规则。 |
| 完成检查 | 用户先挂载并成功运行，再调用该注册返回的清理函数并重新运行。只有目录不含该工具、运行进入“能力不可用”分支，且用户指出无需编辑主循环，才通过。 |
| 最多 3 个新术语 | `plugin`：把一组注册动作装入运行环境的单元；`effect`：由运行环境跟踪、带清理动作的注册；`disposer`：执行后撤销该次注册的函数。共 3 个。 |
| `claimId` | `dsh-tools-registration-visible`；`dsh-tools-registration-disposer` |
| 教学简化 | 用内存工具目录和同步按钮模拟挂载、释放，不展示 Cordis 配置、作用域继承、shadowing、重名校验、工具 schema 校验或异步 fiber 退出。教学工具只返回固定字符数；真实 DSH 的 `ToolRuntime.register()` 与 effect 所有权在对照层说明。 |
| 默认层篇幅预算 | 体验层 + 理解层共 700 至 900 个中文字符；1 个预测、1 个挂载/释放控制、3 个稳定状态、1 次前后运行对比；目标 7 至 9 分钟。 |
| 展开层篇幅预算 | 最小实现 + DSH 对照共 650 至 850 个中文字符；注册与清理核心代码不超过 25 行；最多 2 张 claim 卡；作用域和 shadowing 只列为后续课入口。 |
| 风险等级 | `A`：新课与可逆生命周期状态机。事实审核重点是 schema 可见性、exact disposer 与 fiber 释放；体验审核重点是让用户观察“恢复原状态”，而不把插件误解成永久修改。 |

### 状态序列

1. **尚未注册：** 工具目录没有“统计文本”，同一任务显示能力不可用。
2. **注册并生效：** 插件把工具加入运行环境；目录出现工具，同一任务得到字符数结果。
3. **释放并恢复：** disposer 撤销该次注册；目录恢复初始集合，同一任务再次进入能力不可用分支。

### 普通语言到术语

先解释“主循环每次都读取当前可用能力，所以新增能力只需加入目录；加入时同时保存一条清理动作，撤下时按这条动作恢复”。用户完成挂载和释放后，再把装载单元命名为 `plugin`，把可追踪注册命名为 `effect`，把清理函数命名为 `disposer`。

## 跨课依赖与退出条件

```text
01 工具结果改变回答
  ├─> 02 完整记录投影为模型消息
  └─> 03 注册表改变可用工具
```

- 第 01 课冻结前，必须确认两个 claim 没有把 `tools/execute` waterfall 说成多工具并发。
- 第 02 课冻结前，必须用固定提交核对事件类型、surface 成员和 log-only 反例。
- 第 03 课冻结前，必须核对注册、schema 可见性、手动 disposer 和插件 fiber 释放四个状态。
- 任一 claim 被判为“需限定”时，先更新 `claims-v1.yaml` 的 statement 或 caveat，再改后续课程正文；被判为“错误”或“当前无证据”时撤回对应教学结论。
