# Learn Agent Harness 产品简报

> 状态：需求候选稿，未冻结。**一句话产品：** 从一次看得见的 Agent 任务出发，先获得直觉，再逐层看懂 DeepSeek Harness 如何调用工具、记录过程和扩展能力。

## 核心用户

主用户是会读基础 JavaScript、TypeScript 或 Python，使用过聊天式或编码 Agent，但没有维护过 Agent runtime 的应用开发者。他通常想完成三件事：

- 判断 DSH 是否适合自己的 Agent 项目。
- 把工具调用、上下文或执行轨迹与真实机制对应起来。
- 修改 DSH 前找到正确的服务、事件和包，而不是直接猜 monorepo 入口。

产品默认他会基础编程，但不默认他理解 Cordis、waterfall、shadowing、SessionEvent 或 Provider。

### 非用户

- 只想使用成品 Agent、没有编程需求的终端用户。
- 只需要 API 字段或配置表的维护者。
- 只想复制生产部署模板的运维人员。
- 已熟悉 DSH 内部实现、只需要源码搜索的核心维护者。

这些人可以获得明确的参考入口，但不改变主学习路径的难度。

## 首次体验

首屏不展示 22 课目录、七阶段架构图或代码行数。

用户首先看到一个具体任务：

> 看一个 Agent 如何查找信息、调用工具并给出答案。

首次体验按以下顺序进行：

1. 用户看到任务、预期结果、预计时间和唯一主操作。
2. 用户先预测 Agent 下一步会直接回答还是调用工具。
3. 用户启动任务，观察“请求 -> 决策 -> 工具 -> 结果 -> 停止”。
4. 页面只标出两个关键状态变化，不立即解释全部工程概念。
5. 用户用自己的话判断为什么任务能完成。
6. 产品再给刚才的机制命名，并提供“继续理解”和“查看真实 DSH”两个深度入口。

正常路径应在 90 秒内出现首次可见结果。移动端首屏必须直接看到任务和主操作，课程目录进入抽屉或独立页面。

## 三个纵向切片

编码前只冻结以下三课。它们共同验证首页、课程模板、运行反馈、进度、搜索、真实源码对照和事实校验，不先扩写完整课程。

| 切片 | 用户任务与可见结果 | 只回答一个问题 | 状态变化 | 随后命名 | 完成条件 |
|---|---|---|---|---|---|
| 一：完成工具任务 | 查找信息并回答；Agent 选择工具、接收结果并停止 | Agent 为什么没有直接回答？ | 从“只有请求”变为“产生工具结果和最终回答” | Agent loop、工具调用 | 改变工具结果，预测最终回答如何变化 |
| 二：回看回答依据 | 连续提问后回放请求、工具调用、结果和回答 | 聊天界面中的消息从哪里来？ | 从“只看最终文本”变为“从记录还原模型视图” | SessionEvent、消息投影、Turn / Step | 隐藏或替换记录，预测模型视图如何变化 |
| 三：加入并撤销能力 | 加入一个工具或拦截规则，再移除它 | 为什么新增能力不需要修改主循环？ | 从“能力不可用”变为“注册并生效”，再恢复为“已撤销” | Cordis 插件、effect、类型化事件、工具注册 | 改变一个注册项，预测能力可见性和行为变化 |

## P0 成功指标

以下是首轮产品门槛，不是当前产品数据：

- 至少 5 名核心用户参加纵向切片可用性测试。
- 至少 4 人无需主持人解释即可找到首屏主操作并获得首次结果。
- 首次可见结果在正常目标环境中不超过 90 秒。
- 至少 4 人能指出每课的关键状态变化。
- 至少 3 人能完成一个未见过的相邻迁移题。
- 三课教学结果均可在干净环境复现。
- 390 x 844 视口首屏可见任务、预期结果和主操作。
- 键盘可完成主路径，且不存在 P0/P1 无障碍问题。
- 所有 DSH 产品事实都有固定提交证据，不存在已知事实错误。
- 主要反馈从“看不进去、不知道从哪开始”转为具体课程或机制问题。

## 明确不做

- 不复制参考站点后只更换视觉样式。
- 不用 monorepo 包目录或 22 课清单组织首页主路径。
- 不在首次体验解释 Cordis、事件模式和完整架构。
- 不把 Python 教学模型描述为生产 SDK 或真实 DSH API。
- 不替代 DSH 的 API、配置和维护者架构参考。
- 不在三课切片验证前批量改写完整课程。
- 不为提高完成率加入排行榜、连续签到或强制登录。
- 不在没有权威证据时补写“合理但未验证”的产品行为。
- 不把浏览时长或翻页数量当作理解成功。

## 编码前 GO / NO-GO 门

### GO

只有以下条件全部满足，才进入三课纵向切片编码：

- 核心用户、非用户和一句话产品已由 PM 确认。
- 首次体验流程及三个切片的输入、输出和状态变化已写定。
- 每课都满足“一问、一变、一机制”，并有可执行完成条件。
- 桌面与 390 px 移动端低保真流程已评审。
- 三课事实声明表已由 DSH 事实审核人确认。
- P0 指标、测试场景、无障碍要求和测量事件已明确。
- 参考仓库可复用资产、许可证和署名方式已确认。
- PM、内容、事实、设计和开发负责人均明确通过。

### NO-GO

出现任一情况就继续产品或原型工作，不进入编码：

- 首屏仍以课程目录、阶段图或工程术语作为主要内容。
- 用户需要主持人解释才能找到主操作或理解预期结果。
- 任一切片同时教授多个无关机制，无法指出唯一状态变化。
- 教学模型与真实 DSH 的差异会改变课程结论。
- 存在未解决的产品事实错误、P0 分歧或许可证问题。
- 移动端正文仍排在完整导航之后。
- 团队计划先搭完整站点或改写全部课程，再验证三个切片。

完整生产与验收流程见 [PM-SOP.md](./PM-SOP.md)。
