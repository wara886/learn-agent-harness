# Learn DeepSeek Harness 纵向切片需求

> 状态：M0 已确认，2026-08-15 进入三课纵向切片开发
> 产品范围：独立的 learner-first 学习体验，不是 DSH 产品补丁，也不是营销 landing page
> 参考基线：`onychen/learn-dsh@249f4a0e9622917c8d315c672c87b96401a0c7d4`
> 事实基线：`deepseek-harness@47f943859bef60e4160492346772ded9b24f765a`
> 证据：`PM-SOP.md`、`research/reference-content-audit.md`、`research/session-ux-bug-audit.md`、`research/open-source-ux-landscape.md`

## 1. 决策结论

**GO：** 进入“三课纵向切片”的设计与开发准备。首版验证一个命题：不了解 Cordis、事件模式和 DSH 包结构的应用开发者，能否先通过一次可操作的 Agent 过程获得结果，再逐层理解背后的机制。

**NO-GO：** 当前不得直接重写 22 课、复制参考站信息架构、修改 DSH 本体、接入真实模型、搭建账号或分析后台，也不得把参考课程的示例和事实未经复核迁入新项目。

用户原话“感觉太工程了，都看不进去”是本产品的首要问题，不按视觉偏好处理。它被转成以下三个可验证结果：

1. 用户不读目录和架构说明，也能在 30 秒内找到主操作。
2. 用户在 90 秒内完成首次演示并看到完整结果。
3. 用户完成后能指出至少一个关键状态变化，并用普通语言说明 Agent 为什么采取下一步行动。

验证分为两道门。M0 使用无应用代码的桌面/移动低保真或可点击设计原型测试 5 名目标用户：至少 4 人在 30 秒内找到主操作，至少 4 人能沿原型看到结果并指出关键状态变化，达标后才进入 scaffold。M4 再使用真实 production build 测试至少 5 人：至少 4 人在 90 秒内完成首次演示，至少 4 人能解释状态变化，至少 3 人通过相邻迁移题。两轮不混用测试记录；实现完成但未经过 M4 验证，只能称为“可用原型”，不能称为已验证产品。

## 2. 产品边界

### 2.1 本仓库负责什么

- 用任务而不是包目录组织学习路径。
- 提供无需密钥、不会产生 API 费用的确定性概念演示。
- 用“预测 -> 操作 -> 观察 -> 改一个变量 -> 迁移检查”完成学习闭环。
- 把普通语言解释、最小实现、真实 DSH 对照分层展示。
- 为每项 DSH 产品事实保留固定提交、源码位置和教学差异。
- 提供问题语言入口、三课进度恢复、响应式和无障碍体验。

### 2.2 本仓库不负责什么

历史会话确认了三项 DSH P0：委派树没有总预算；Web 切换 Pro 后 child 可能从过期的 `parent.options` 继承 Flash；交付后 descendants 仍可继续消费，并由 report/settlement 反复唤醒父链。这些必须进入 DSH 产品 PR，不得用学习网站的视觉呈现冒充修复。

以下事项同样属于 DSH 本体 backlog：

- child 模型、来源、终态和成本投影；
- 树级取消及 quiescence 回执；
- 只读源码位置的可点击跳转；
- Chat 主流虚拟化和真实 fan-out 性能基准；
- `models.dev` 成本投影、LiteLLM 部署试点、Tauri 桌面壳和 OTel/Langfuse 适配。

学习产品可以在未来用明确标记的案例解释“当前行为、已知缺口、建议修复”，但首个三课切片不把这些缺口当作课程主线，也不宣称第三方集成已经存在。

## 3. 目标用户与成功任务

### 3.1 主用户

会读基础 JavaScript、TypeScript 或 Python，使用过聊天式或编码 Agent，但没有维护过 Agent runtime，也不了解 Cordis 和 DSH 内部包结构的应用开发者。

### 3.2 首次成功

用户从第一屏直接运行一个本地概念演示，看见“任务 -> 模型决定调用工具 -> 工具返回 -> 模型形成回答 -> 停止”的完整过程，并知道这不是一次真实 API 调用。

### 3.3 三课完成后的能力

用户能够：

1. 解释 Agent 为什么需要工具结果后再回答。
2. 区分“完整事件记录”和“模型当前看到的消息投影”。
3. 解释插件如何增加一项能力，以及释放后为什么能力消失。
4. 按需找到对应的真实 DSH 源码与限定条件，但不依赖读源码完成主路径。

## 4. 三课纵向切片

| 课 | 用户任务 | 核心状态变化 | 默认层引入术语 | 完成检查 |
|---|---|---|---|---|
| 01 让 Agent 先查再答 | 从示例工作区找出发布端口并说明依据 | 用户任务变为 tool call，tool result 再变为最终回答 | Agent loop、tool call | 将工具结果改为“拒绝访问”后，选择不会编造答案的结束行为 |
| 02 从记录还原它看到的内容 | 用上节执行事件生成模型视图 | 完整追加日志被投影成较小的消息表面 | SessionEvent、surface、projection | 加入一个 log-only 事件，判断模型视图应保持不变 |
| 03 加一项能力，再完整撤下 | 挂载并释放一个统计文本的插件 | 工具目录新增能力，disposer 执行后恢复原状态 | plugin、effect、disposer | 释放插件后重新运行，确认 Agent 不再看到该工具 |

课程任务和文件均为“概念演示”，不得伪装成真实 DSH 配置或 API。真实名称、事件字段和实现位置只在 DSH 对照层出现。

## 5. P0 需求

### R0-01 第一屏就是可操作的学习体验

- `1440 x 900` 和 `390 x 844` 首屏必须同时看见产品名、一个具体任务、预计用时、演示性质、唯一主操作和交互区起始状态。
- 完整目录、架构图、包名列表、课程行数和阶段图例不得出现在主操作之前。
- 第一屏不是功能介绍、品牌宣传或营销 hero；主视觉就是可运行的任务状态。
- 390 px 宽度下导航不得把正文推到首屏之后，不允许把完整侧栏堆在正文上方。

### R0-02 首个结果短、真、可解释

- 用户进入后一次主要点击即可开始；不要求安装、登录、输入密钥或先阅读源码。
- 点击后 100 ms 内出现明确的运行状态；本地确定性演示在常规开发机上 2 秒内结算，不添加伪造等待时间。
- 演示附近明确写明“本地概念演示，不调用模型，不产生 API 费用”。
- 结果必须包含任务答案、依据、停止状态和可展开的执行过程，不能只播放装饰动画。

### R0-03 每课形成完整学习闭环

每课必须按顺序提供：一个可验证的预测、一个主操作、2 至 3 个状态变化、一个普通语言解释、一次单变量实验、一个迁移检查。只有实验或检查点通过才记录完成，不以滚动或停留时间代替。

### R0-04 默认路径按需披露工程信息

- 体验层和理解层默认展开；最小实现与真实 DSH 对照默认折叠，但可通过稳定链接直达。
- 首次结果之前不得出现 Cordis、waterfall、`SurfaceOp`、capability seam 或包路径。
- 每课默认路径最多引入 3 个新术语；术语出现前先用普通语言完整解释现象。
- 代码和源码位置不得成为完成核心路径的前置条件。

### R0-05 控制阅读负担

- 每个页面只有一个主任务；辅助动作在层级、位置和对比度上明确降级。
- 默认步骤一次只要求一个决定，不并排展示课程目录、源码、事件原文和解释全文。
- 每课核心路径以 5 至 12 分钟为目标；超出的内容移到实现层或拆分。
- 首轮可用性测试必须记录首个停顿点、误解词和放弃点，不用“页面停留越久”代表学习更好。

### R0-06 教学模型与产品事实分开

- 每个演示显示“概念演示”标识，并列出会改变真实行为理解的省略项。
- 每项 DSH 产品事实有唯一 `claimId`、固定提交、仓库、路径、符号或测试、事实分类和审核状态。
- 对事件模式、联合类型、角色名称和源码路径建立自动检查；不能自动证明的语义必须有人工审核记录。
- 页面显示“适用于 DSH `47f943859b`”，源码链接使用固定提交 URL，不链接会漂移的默认分支。
- 参考课程是待审计输入，不是事实来源。

参考审计确认的七项错误不得回归：`tools/execute` 是 waterfall；追加写作 `surfaceOp: 'append'`；replace 引用全部被遮蔽节点；Prompt 文本和工具 schema 分离；角色名为 Service Definition / Service Provider / Consumer；`skills/change` 只陈述已验证的发射行为；课程数量与标题一致。

### R0-07 用户可以按问题找到课

- 顶部入口使用“它为什么先读文件”“它怎么记住刚才发生的事”“能力为什么能被撤下”等用户语言。
- 搜索覆盖标题、普通语言问题、故障现象、术语和权威源码位置，不能只匹配课程 metadata。
- 首版至少通过以下查询：`为什么要调用工具`、`它记住了什么`、`事件怎么变成消息`、`怎么加工具`、`插件怎么撤销`。
- 无结果状态提供三个现有问题入口和“查看三课地图”，不显示空白页。

### R0-08 进度真实、可恢复、可清除

- 本地记录最近课程、最近步骤、已通过检查点和内容版本，不要求账号。
- 返回首页优先显示“继续上次任务”，不是再次展示课程总览。
- 用户可重置当前课或清除全部进度；清除前说明范围，执行后状态立即一致。
- 浏览器拒绝存储时主路径仍可完成，并明确说明本次进度不会保存。
- 内容版本不兼容时安全重置受影响进度，不把旧状态解释成已完成。

### R0-09 运行与完成状态透明

- 交互状态使用明确、互斥的词：未开始、运行中、等待操作、已完成、未通过、演示错误。
- “已完成”只在所有确定性步骤结算后出现；完成后没有隐藏计时器、网络请求或后台工作。
- 过程默认摘要为动作、目标、状态和结果；原始事件和参数按需展开。
- 教学中提到 DSH `running`、`idle` 或 `ready` 时，不得把 `ready` 等同于任务成功。

### R0-10 响应式行为可预测

- 验证视口至少包含 `390 x 844`、`768 x 1024`、`1440 x 900`。
- 窄屏采用正文优先的单列顺序；课程地图与次级导航进入抽屉或独立页面。
- 事件表和代码允许自身横向滚动，但页面不得产生横向溢出。
- 文本、按钮、进度和状态标签在最长中文文案、200% 缩放和触摸输入下不遮挡、不截断。
- 固定格式的时间线、步骤控制和状态块使用稳定尺寸，状态变化不得造成无意义布局跳动。

### R0-11 主路径达到基础无障碍门槛

- 使用语义链接、按钮、表单标签、标题层级和 landmark；不得用带点击监听的 `div` 充当课程入口。
- 键盘可以完成首次演示、三课预测、实验、检查点、搜索、详情展开和进度清除。
- 每个控件有可访问名称、可见焦点和至少 `44 x 44 px` 的触摸目标。
- 动态状态使用克制的 live region；焦点在路由和步骤切换后移动到可预期位置。
- `prefers-reduced-motion` 保留状态变化但去掉非必要位移；颜色不是唯一状态编码。
- 自动 axe 检查无 serious/critical 问题，人工检查 VoiceOver 名称、顺序和状态播报。

### R0-12 静态原型保持轻量和稳定

- 首屏不依赖后端、WebSocket、模型 API、远程字体或运行时拉取第三方价格数据。
- 推荐方案的首屏 JavaScript gzip 预算为 180 KiB；超出必须给出依赖和用户收益说明。
- 课程内容缺失、状态迁移非法或事实清单无效时构建失败，不在运行时静默跳过。
- 错误状态提供重试或重置动作，且不会把失败记录成课程完成。

### R0-13 首版不远程收集学习数据

- 纵向切片不接入第三方分析、广告、用户标识或远程日志。
- 可用性指标通过受控测试表和浏览器测试产物收集；页面本地进度不得包含用户源码或聊天内容。
- 后续若引入匿名统计，必须先定义最小事件字典、保留期、退出和清除机制，再单独评审。

### R0-14 许可证、署名和独立性清楚

- 新仓库采用 MIT 许可证，并保留自身版权信息。
- 若复用参考项目或 DSH 的实质代码、讲义或资源，`THIRD_PARTY_NOTICES.md` 保留相应 MIT 版权和来源提交。
- 首版默认采用 clean-room 重写：可参考主题和证据，不直接复制参考站生成器、Markdown renderer、页面代码和视觉资源。
- README 明确这是独立学习项目，不是 DeepSeek 官方产品；不使用未确认授权的商标图形或品牌资源。

### R0-15 每次发布都有可复核证据

- 单元、组件、端到端、内容、事实、无障碍、响应式和构建检查全部通过后才部署。
- 保存三个关键视口截图、键盘路径记录和一份真实构建 GIF；GIF 必须注明它展示的是本地确定性概念演示，而不是模型 API。
- 发布记录包含演示提交、服务来源、测试命令、事实基线和已知限制。
- GitHub Pages 上的生产 URL 完成一次冷启动回归；上一构建可通过 revert 与重新部署恢复。

## 6. P1 与 P2

### P1：三课验证后

- 扩展到六个任务章节、术语索引和真实源码索引。
- 进度 JSON 导出、跨课程复习和可分享的检查点。
- 更完整的问题搜索与无结果查询研究。
- 构建期生成源码差异报告，辅助升级 DSH 固定提交。
- 解释 DSH 委派预算、模型继承、终态和成本问题的独立案例课，但明确区分当前事实与建议设计。

### P2：有证据再决定

- 真实 DSH 运行沙箱、真实模型调用或用户自己的 API key。
- 登录、跨设备同步、社区作业、AI 导师和个性化路线。
- PWA 离线安装、国际化和公开学习数据分析。

## 7. 非功能与内容数据约定

每课必须使用结构化内容，而不是从 Markdown 标题猜测交互逻辑。最低字段为：

- 身份：`id`、`slug`、内容版本、标题、用户问题、预计用时、前置课；
- 教学：预期能力、最多 3 个新术语、普通语言解释、迁移目标；
- 交互：初始状态、预测选项、确定性状态迁移、可观察变化、单变量实验、检查点判定；
- 深度层：最小实现、DSH 对照、教学简化；
- 搜索：用户问题、故障现象、术语、源码符号；
- 证据：`claimId` 列表、固定提交和审核状态；
- 完成：可机器判断的完成规则。

非法状态迁移必须显式失败；不得根据按钮点击次数或页面滚动位置推断理解。

## 8. 验收样本

### 冷启动样本

用户首次打开首页，不展开目录，在 30 秒内找到并启动演示，在 90 秒内看到带依据的答案，并正确说出“它先读了文件，得到结果后才回答”。

### 问题入口样本

用户搜索“事件怎么变成消息”，直接进入第 02 课，在不读源码的情况下完成投影实验，并判断 log-only 事件不会进入模型视图。

### 回访样本

用户完成第 01 课并离开，重新打开后从“继续上次任务”回到准确步骤；随后清除进度，首页和课程状态同时恢复为未开始。

### 工程深度样本

用户在完成核心路径后展开 DSH 对照，能看到固定提交、权威符号、教学省略和源码链接；关闭详情不会丢失课程状态。

## 9. 待确认项

以下两项是实施前确认，不影响需求本身的完整性：

1. **技术栈：** 推荐 React + TypeScript + Vite 的静态 SPA；理由和替代方案见 `IMPLEMENTATION-PLAN.md`。用户确认前不创建 scaffold。
2. **视觉方向：** 需求只冻结 learner-first 层级、正文优先和状态透明；具体配色、字体与视觉世界需在实施前以一个方向稿确认。

名称与域名不阻塞原型：仓库暂用 `learn-deepseek-harness`，公开名称可在首次部署前调整。具体参与者姓名不阻塞需求文档审核，但完成招募、无应用代码的 M0 原型测试和测试记录是进入 M1 开发的硬门；M4 还要用真实构建完成另一轮至少 5 人发布验证。任一轮未达标都不得扩写完整课程。

## 10. 冻结条件

只有以下条件全部满足才进入应用代码：

- 根审核确认本需求未把 DSH 产品问题混入学习网站实现；
- 用户确认技术栈推荐和视觉方向；
- 桌面/移动低保真或可点击设计原型完成 M0 的 5 人测试并达到进入门槛；
- 三课任务、完成条件和事实清单被 DSH 事实审核人接受；
- 每项 P0 在实施计划中有实现切片、自动或人工验证与证据产物；
- 许可证与仓库公开策略没有阻塞项。
