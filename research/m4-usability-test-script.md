# M4 五人发布可用性测试脚本

> 测试对象：`https://wara886.github.io/learn-agent-harness/`
> 发布基线：`v0.5.0-beta.1`
> 参与者：5 名符合目标用户定义、未参与产品设计的人
> 单人时长：15 至 20 分钟

## 发布门槛

1. 5/5 参与者均为会基础编程、使用过聊天或编码 Agent、但没有维护过 Agent runtime 的目标用户。
2. 至少 4/5 无需主持人提示，在 90 秒内获得第一课首次结果。
3. 至少 4/5 能用自己的话解释第一课中工具结果如何改变最终回答。
4. 至少 3/5 能正确完成未提前讲解的迁移题。

四项必须同时达到才输出 `M4_GATE=PASS`。浏览器自动化、设计审核、开发者演示和模拟角色不计入参与者。

## 准备

- 为每人使用新的浏览器访客窗口，确认页面顶部进度为 `0/10`。
- 至少两人使用手机或 `390 x 844` 等效窄屏，至少两人使用桌面浏览器。
- 用匿名编号 `P01` 至 `P05` 记录，不收集姓名、账号或联系方式。
- 主持人只读任务，不解释按钮、术语、正确答案或页面结构。
- 从参与者第一次看到页面开始计时，到页面出现“发布端口是 4173，依据为 config.env；任务已停止。”时结束。

## 开场白

> 这次测试的是产品，不是你。请边看边说你在找什么、为什么准备点某个位置。页面不会调用真实模型，也不产生 API 费用。遇到不确定时请按自己的理解继续，我不会提示正确操作。

## 任务 A：得到第一次结果

主持人说：

> 你想知道这个 Agent 怎样找出项目的发布端口。请从当前页面开始，并在看到明确结果时告诉我。

记录以下事实：

- 是否无需提示完成；
- 首次结果用时，精确到秒；
- 是否出现误点、返回或求助；
- 参与者认为下一步是什么。

主持人若被问“应该点哪里”，只回答“请按你的理解继续”，并把 `usedFacilitatorHelp` 记为 `true`。

## 任务 B：解释状态变化

参与者完成“拒绝访问”实验后问：

> 前后什么保持不变，什么发生了变化？为什么最后的回答不同？

准确解释必须同时包含：任务不变；工具结果从端口值变为拒绝访问；缺少依据后不再报告 4173。主持人可问“还有吗”，但不能说出这三个对象。

## 任务 C：未见迁移题

在参与者回答页面迁移题之前，不解释 Agent loop、tool call 或正确结束方式。参与者独立选择后，按页面实际结果记录 `transferQuestionPassed`。

## 任务 D：Pi 入口发现

完成第一课后问：

> 现在请找到 Pi 的课程，并告诉我它和刚才这课最明显的关系是什么。

本任务只记录轨道入口是否易发现及参与者原话，不进入四项发布门计算。

## 收尾问题

1. 哪一步最不像下一步？
2. 哪个状态最难区分？
3. 哪个词需要停下来理解？
4. 你会用什么话向同事解释刚才发生的过程？

只记录参与者原话和可观察行为，不把主持人的解释写成参与者结论。

## 录入与汇总

将结果写入 `research/m4-usability-results.json`，未测试字段保持 `null`。运行：

```sh
pnpm test:m4
```

五条记录不完整时脚本输出 `M4_GATE=PENDING`；完整后只输出可复算的 `PASS` 或 `FAIL`。
